# PR #228: final local validation

This change reuses the receiver's refinement cell queues within an 8 MiB retention budget. The intended drawing, bin values, flux accounting, controls and exports stay identical. The benefit is less allocation during repeated receiver frames; a visible speedup is not promised.

```sh
npm run dev -- --port 5178 --strictPort
```

## Experience the change

1. Open the 480-bin cone. In the receiver controls, confirm **Bins** is 480 and **Refinement levels** is 2. The tilted screen should carry a smooth patch of light, with a flux note below the drawing and no validation error.
2. Open the animation section and choose **Play animation**, then **Pause**. Scrub **Animation progress** from the start to the middle and back. The screen turns from 20° to 75° and back, changing its section of the cone from an ellipse through a parabola to a hyperbola. Repeated visits should reproduce the same drawing and flux note without stale patches of light. **Stop** restores the opening study.
3. Open the 960-bin link and repeat a short playback. Change **Refinement levels** through 3, 0 and 2, waiting for each result. Zero levels can look coarser; returning to 2 should restore the refined result. Change **Bins** to 480 and back to 960, then reopen the link to restore everything.
4. While stopped, enable **Refine the receiver to the view**. Zoom and pan, then wait for the finer inset. The full-window accounting remains the same when only the camera changes. Play: the view inset disappears during playback. Stop: it returns after the view settles. Disable the option: the ordinary receiver remains.
5. Open the glass-dome link, then reopen the cone link. Each must restore its own light pattern, controls and camera. This exercises replacement of the cached ray family. Also try choosing an unrelated notebook example and returning through the link.
6. Change the theme and inspect the receiver in light and dark. Narrow the browser window and confirm the drawing and controls remain usable. Save a PNG through **Export image** while stopped; open the downloaded image and check its light pattern, camera and theme against the live drawing.

For performance impressions, use a production build (`npm run build`, then `npm run preview -- --port 5178 --strictPort`) and the same links. Development-mode playback is slower. Allocation reduction is verified by the engine test; visual smoothness alone cannot establish it. A phone check is useful for playback comfort and remains a hands-on check over HTTPS (`make preview-lan`), not a result established by desktop automation.

## Acceptance

The drawing and exports retain the same light, gaps and accounting across repeated movement, refinement changes, view insets and study replacement. No new feature or control should appear. Report the study link, settings, browser and action sequence if anything differs. These human checks complement the automated review and final verification recorded in the PR.
